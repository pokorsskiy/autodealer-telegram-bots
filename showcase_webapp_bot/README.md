# Web App-бот: каталог и админка

Telegram Web App с публичным каталогом автомобилей, заявками менеджеру и
закрытой веб-админкой.

## Возможности

Публичный интерфейс:

- стартовый экран и категории «В городе» / «В порту»;
- поиск, фильтры и сортировка каталога;
- представление плиткой и списком;
- избранное в рамках текущей сессии;
- фотогалерея и подробная карточка автомобиля;
- автоматическая подстановка выбранного автомобиля в заявку;
- форма персонального подбора и предварительный калькулятор.

Закрытая админка:

- авторизация по логину и паролю;
- вход без пароля из Telegram: команда `/admin` в боте (см. ниже);
- роли владельца и менеджера;
- создание, редактирование и скрытие карточек;
- изменение цены, характеристик и статуса;
- загрузка и удаление JPG, PNG и WEBP до 8 МБ;
- удаление автомобилей только владельцем;
- управление учётными записями только владельцем.

## Настройка

Создайте локальный `.env` по образцу `.env.example`.

- `BOT_TOKEN` — токен showcase-бота;
- `DEMO_MODE` — обязательно, без него не запустятся ни бот, ни сервер: `1` — демо, сервер не принимает заявки, витрина показывает плашку «Демо, не оферта» и вместо отправки — образец заявки; `0` — рабочая витрина заказчика;
- `SITE_OWNER` и `SITE_EMAIL` — владелец сайта для подвала: ФИО или название и почта;
- `LEAD_NOTIFY_CONTACTS=0` — уведомление о заявке приходит в Telegram без имени, телефона и профиля клиента: номер, машина и кнопка «Открыть админку», контакты — в админке. Так данные клиентов не проходят через зарубежные серверы Telegram (ст. 12 152-ФЗ). Включать у заказчиков на российском сервере; по умолчанию `1` — полная заявка;
- `TELEGRAM_API_URL` — необязательно: адрес посредника к Bot API, если сервер стоит в России и `api.telegram.org` с него недоступен; пусто — запросы идут напрямую;
- `legal.json` (рядом с `.env`, образец — `legal.example.json`) — реквизиты оператора персональных данных для страниц `/privacy` и `/consent`. Рабочей витрине (`DEMO_MODE=0`) файл обязателен: без него страницы отдают 404, а `check_project.py` сообщает об ошибке. В демо страницы показывают образец. Заявка принимается только с отметкой согласия из формы, время согласия хранится в колонке `consent_at`;
- `YOUR_CHAT_ID` — Telegram ID менеджера;
- `WEB_APP_URL` — публичный HTTPS-адрес Web App;
- `DB_NAME` — путь к SQLite;
- `ADMIN_USERNAME` и `ADMIN_PASSWORD` — первоначальный владелец;
- `SECRET_KEY` — случайная секретная строка для подписания сессий;
- `WEB_HOST` и `WEB_PORT` — адрес локального веб-сервера.
- `SESSION_COOKIE_SECURE=1` — передача cookie админки только по HTTPS; для
  локальной проверки по HTTP временно установите `0`.

- `ADMIN_TELEGRAM_IDS` — кому команда `/admin` присылает кнопку админки и кто
  входит по ней без пароля: `Telegram_ID:логин` через запятую, например
  `123456789:owner`. Человек входит с ролью указанного логина; отключённый в
  админке логин не входит и так.
- `ADMIN_EXTRA_BOT_TOKENS` — токены других ботов, из которых тоже открывают
  админку (гибрид). Сервер проверяет подпись Telegram ключом того бота, из
  которого открыт Web App, поэтому без токена вход из гибрида не сработает.
  Этим же токеном гибрид подписывает свои заявки из Web App: сервер принимает
  их на `/api/bot/leads` и показывает в админке вместе с остальными, не
  отправляя второе уведомление. Заявки с сайта сервер дублирует в чаты этих
  ботов тому же `YOUR_CHAT_ID` — без кнопки «Взял в работу»; владелец должен
  хотя бы раз запустить каждого такого бота.

Команды `/admin` нет в меню бота: остальным она ничего не отвечает. Доступ
проверяет сервер по подписи Telegram, а не бот, поэтому адрес `/admin/tg` в
обычном браузере без пароля не пускает.

Первоначальный владелец создаётся при первом запуске, если в БД ещё нет
пользователя с ролью `owner`. Пароль должен содержать не менее 12 символов.
После создания владельца пароль в `.env` не обновляет существующую учётную
запись.

## Запуск

Сервер витрины и бот запускаются из папки `showcase_webapp_bot`; на сервере витрину
запускает gunicorn с `server:app`:

```bash
cd showcase_webapp_bot
python server.py   # витрина и админка на http://127.0.0.1:8000
python bot.py      # Telegram-бот, в отдельном окне
```

Публичный Web App открывается по `/`, админка — по `/admin`.

Для Telegram сервер должен быть опубликован по HTTPS. Рекомендуется запускать
Python-приложение за обратным прокси и направлять `WEB_APP_URL` на тот же домен.
Каталог, API, загруженные фотографии и админка должны обслуживаться этим
сервером, а не отдельным статическим хостингом.

## Проверка

```bash
cd showcase_webapp_bot
python check_project.py
python -m unittest
```

При первой миграции существующая SQLite-база сохраняется в файл `.bak`.
Локальные `.env`, `*.db`, резервные копии и загруженные фотографии не следует
добавлять в Git.

## Обложка меню

`menu-cover.jpg` (1280×720): неоновый контур Porsche Cayenne рядом с телефоном, в котором каталог автомобилей с фильтрами и избранным, — главный экран Web App.

Картинка отправляется фото с подписью при `/start`; после первой отправки Telegram возвращает `file_id`, его можно указать в `MENU_COVER_FILE_ID`, чтобы не загружать файл каждый раз.

## Демо под перегонщика

Работает только при `DEMO_MODE=1`. Ссылка `?brand=Название` подставляет одно
название. Полное демо — `?demo=<имя>`: название, фирменный цвет и машины
из канала перегонщика.

Файлы демо лежат на сервере в `showcase_webapp_bot/demos/<имя>/` и в Git
не попадают — это чужие машины и фото:

- `demo.json` — `{"brand": "АвтоЮг", "color": "#1e6fd9", "cars": [...]}`;
  машины в том же формате, что `web/demo-cars.json`, фото — `/demos/<имя>/<файл>`;
- фото машин рядом с `demo.json`.

Имя — латиница, цифры и дефис, например `avtoyug`.

## Демо-админка

При `DEMO_MODE=1` по адресу `/admin/demo` открывается админка без входа — для
потенциальных клиентов. Все её действия обрабатывает `admin.js` в памяти вкладки
(`demoApi`): машины берутся из публичного каталога или из демо перегонщика
(`/admin/demo?demo=<имя>`), заявки и сотрудники вымышленные. Сессия не создаётся,
настоящие `/api/admin/*` без входа отвечают 401, после обновления страницы всё
возвращается к исходному.
